# cs-dashboard

Terraform for a small AWS stack: a single EC2 instance running ECS (EC2 launch
type) with phpMyAdmin and Metabase, an RDS MySQL database, and an EFS volume
for Metabase's app database. Originally built by hand from an AWS free-tier
tutorial; this repo hardens the Terraform project itself for production use
**without changing the underlying architecture** (no ALB, no Fargate, no NAT
gateway, no autoscaling) - it's still meant to run on free-tier-eligible
resources.

## Architecture

- **Network:** one VPC, 2 public + 2 private subnets across 2 AZs, no NAT
  gateway (private subnets have no internet egress; nothing currently needs
  it - RDS and EFS talk to the ECS instance over the VPC directly).
- **Compute:** one EC2 instance (`t2.micro` by default) in a public subnet,
  running the ECS agent. phpMyAdmin (port 8080) and Metabase (port 3000) run
  as ECS tasks in `bridge` network mode with fixed host ports. Both are only
  reachable from `var.my_ip_cidr`.
- **Database:** RDS MySQL 8.0, private, encrypted at rest, 7-day automated
  backups, deletion protection on by default.
- **Storage:** EFS (encrypted, transit encryption enabled) holds Metabase's
  application database.
- **Logging:** ECS container logs ship to CloudWatch Logs (7-day retention by
  default).

See the inline `# checkov:skip=...` comments throughout the `.tf` files for
the specific security tradeoffs made to stay on free-tier-eligible resources
(e.g. no Multi-AZ RDS, no customer-managed KMS keys, no VPC Flow Logs) - each
one has a one-line reason attached.

## Secrets

There are no secrets in this repository, ever. The RDS master password is
generated by Terraform (`random_password`) and stored only in **SSM
Parameter Store** as a `SecureString`, referenced directly from the RDS
resource. Nobody types it into a file; it's never printed by `plan`/`apply`
(Terraform marks it sensitive) and never touches git.

To read it after `apply`:

```sh
aws ssm get-parameter \
  --name "$(terraform output -raw db_password_ssm_parameter)" \
  --with-decryption --query Parameter.Value --output text
```

## One-time setup: remote state backend

Terraform state is stored remotely (S3 + DynamoDB lock table) instead of
locally, since this project is designed to be safely re-run. The backend
resources aren't hardcoded into this public repo - they're created once via
a small bootstrap config with its own local state:

```sh
cd bootstrap
terraform init
terraform apply
terraform output          # note state_bucket, lock_table, region
cd ..
cp backend.hcl.example backend.hcl   # gitignored - fill in the outputs above
terraform init -backend-config=backend.hcl
```

Keep `bootstrap/terraform.tfstate` somewhere safe after this - it's the one
state file in this project that isn't remote (it manages the remote-state
resources themselves, so it can't depend on them).

## Day-to-day usage

```sh
cp terraform.tfvars.example terraform.tfvars   # gitignored - fill in my_ip_cidr etc.
terraform init -backend-config=backend.hcl      # first time only, or after backend.tf changes
terraform plan
terraform apply
```

Outputs include `phpmyadmin_url`, `metabase_url`, `rds_endpoint`, and
`db_password_ssm_parameter`.

## CI

`.github/workflows/terraform.yml` runs on every PR/push touching `*.tf`:

- `terraform fmt -check` and `terraform validate` (no AWS credentials
  needed - runs `init -backend=false`) for both the root config and
  `bootstrap/`.
- [Checkov](https://www.checkov.io/) static security scanning across the
  whole repo.

There's no `terraform plan`/`apply` job in CI - that needs AWS credentials
(ideally via OIDC, not a long-lived access key), which isn't set up here.
Add one later if you want CI to plan against real AWS state.

## Cost notes

This is designed to run within the AWS free tier for a new-ish account:
`t2.micro` EC2, `db.t3.micro` RDS with 20GB gp2 storage, EFS bursting
throughput, no NAT gateway, no ALB, no Multi-AZ. The main things that can
accrue cost over time are RDS backup storage beyond your allocated storage
size, and EFS storage beyond the free-tier allowance if Metabase's DB grows.
